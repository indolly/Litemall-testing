# 03 跨端业务闭环测试用例

这些用例验证的不是单个页面，而是“管理端配置/处理 → 用户端行为 → 接口响应 → 数据库状态”的完整业务事实。

| ID | P | 业务闭环 | 前置/数据 | 操作 | 核心预期与证据 |
|---|---:|---|---|---|---|
| E2E-001 | P0 | 商品创建到购买 | 后台有分类品牌 | 后台创建并上架多 SKU 商品→用户搜索详情→加购→提交订单 | 用户端字段与后台一致；订单保存快照；库存扣减；接口 `errno=0`；商品/SKU/订单表证据完整 |
| E2E-002 | P0 | 商品改价 | 商品已在购物车且有历史订单 | 后台改价→用户刷新购物车并再下单 | 购物车/新订单使用新价；历史订单仍为旧快照；数据库可追溯 |
| E2E-003 | P0 | 商品下架 | 商品已在搜索和购物车 | 后台下架→用户搜索、旧详情、购物车和结算 | 新入口不可见；旧入口不可购买；不能提交下架商品 |
| E2E-004 | P0 | 库存 N/N+1 | SKU 库存 N | 用户购买 N 成功→尝试再买 1；取消成功订单 | 不超卖；库存扣减准确；取消后按规则恢复且只恢复一次 |
| E2E-005 | P0 | 两用户最后库存竞争 | 库存 1，用户 A/B | 同时提交 | 至多一个订单成功；失败方明确；数据库库存非负 |
| E2E-006 | P1 | 分类品牌联动 | 已有商品 | 后台调整商品分类/品牌→用户端分类、品牌、搜索查看 | 新归属生效，旧归属消失；无重复/孤儿数据 |
| E2E-007 | P1 | 首页广告专题联动 | 有广告和专题 | 后台创建/启停/删除→用户首页点击 | 展示时间、排序、跳转及失效处理一致 |
| E2E-008 | P0 | 优惠券完整生命周期 | 后台创建限量券 | 用户领取→结算使用→提交→取消 | 发放与个人限额正确；使用后占用；取消后恢复；券和订单关联一致 |
| E2E-009 | P0 | 优惠券并发限量 | 总量 1 | 两用户同时领取 | 只有一个成功；库存不为负；失败提示明确 |
| E2E-010 | P0 | 普通订单生命周期 | 可售商品、有效地址 | 提交→支付沙箱/Mock→后台发货→用户确认→评价 | 状态只按允许路径迁移；时间、物流、库存、评价和日志一致 |
| E2E-011 | P0 | 未支付订单取消 | 待付款订单使用优惠券 | 用户取消→再次取消→查后台和数据库 | 状态取消；库存/券恢复一次；后台同步；重复操作无副作用 |
| E2E-012 | P0 | 支付回调幂等 | 待付款订单 | 对同一订单发送两次合法回调 | 只记一次支付；状态不倒退；无重复通知/团购成员 |
| E2E-013 | P0 | 后台发货权限与用户同步 | 待发货订单、受限管理员 | 无权限角色发货→有权限角色发货 | 前者被服务端拒绝；后者成功；用户端显示物流 |
| E2E-014 | P0 | 售后受理退款 | 已完成可售后订单 | 用户申请→后台受理→退款→用户查看 | 售后与订单状态同步；金额正确；库存按规则恢复；退款不可重复 |
| E2E-015 | P0 | 售后拒绝 | 用户申请售后 | 后台填写原因拒绝→用户查看/再次申请 | 拒绝原因可见；状态一致；再次申请遵守产品规则 |
| E2E-016 | P0 | 售后取消 | 申请中 | 用户取消→后台查询 | 两侧均为取消；后台不能再受理/退款 |
| E2E-017 | P0 | 团购成功 | 后台建立人数 2 的规则 | A 开团支付→B 参团支付 | 两订单和团成员关联正确；达到人数后团状态成功 |
| E2E-018 | P0 | 团购失败边界 | 进行中的团购 | 活动过期/后台下线后继续参团 | 新参团被拒绝；已有订单按规则处理；状态可解释 |
| E2E-019 | P1 | 用户反馈到后台 | 用户登录 | 用户提交反馈→后台按用户/类型查询 | 文本、联系方式、用户和时间一致；特殊字符安全展示 |
| E2E-020 | P1 | 商品评价到后台 | 已确认订单 | 用户评价→商品详情查看→后台查询/删除 | 三端内容一致；删除后用户端不显示且计数更新 |
| E2E-021 | P1 | 商城配置联动 | 管理员有配置权限 | 修改商城名称/联系方式→用户关于页刷新 | 用户端读取新值；重启后仍保存；无缓存长期不一致 |
| E2E-022 | P0 | 角色权限闭环 | 创建仅有商品查看权限角色 | 登录后台→尝试查看、创建、删除商品及直接调用 API | 只能查看；创建删除菜单和服务端均拒绝；操作日志可追踪 |
| E2E-023 | P0 | 跨用户数据隔离 | 用户 A/B 均有地址、购物车、订单、售后 | B 使用 A 的各类 ID 构造请求 | 地址/购物车/订单/评价/售后全部拒绝；A 数据不变 |
| E2E-024 | P0 | 网络未知结果恢复 | 提交订单时客户端断网 | 在响应前断网→恢复后查订单和购物车 | 客户端不盲目重提；根据服务端事实恢复；无重复订单 |
| E2E-025 | P1 | 缓存一致性 | 首页/商品存在缓存 | 后台更新展示数据→按缓存策略刷新/清缓存 | 生效时间符合设计；清缓存后数据一致；不长期返回已删除内容 |

## 执行证据模板

每条闭环用例至少保留以下证据：

1. 管理端或用户端关键步骤截图。
2. 关键 HTTP 请求：方法、URL、请求参数、身份和响应业务码。
3. 操作前后的数据库查询，只查与本用例相关的稳定字段。
4. 失败时记录请求时间并截取对应服务端日志和首个业务栈帧。
5. 若发现缺陷，关联禅道编号；修复后复测失败点，并回归同状态机的相邻路径。
