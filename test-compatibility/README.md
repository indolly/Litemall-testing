## 运行前提

- Litemall 后端和 MySQL 已启动，`/wx` 接口可访问；
- H5 开发服务器已启动并监听 `http://127.0.0.1:6255`；
- 本机安装 Node.js、Chrome 和 Edge；
- H5 登录数据从已被 Git 忽略的 `test-automation/test_config.local.json` 读取，脚本和报告不保存账号密码或 Token；
- 小程序运行态测试需要微信开发者工具，并开启“设置 → 安全设置 → 服务端口”。

### 微信小程序运行态兼容性

使用微信开发者工具内置自动化接口，在 iPhone 12/13 (Pro) 模拟器、390×844 视口、微信 8.0.5、基础库 3.17.3 下执行 12 个核心场景，结果为 12 PASS、0 产品失败。

覆盖首页、分类、搜索、商品详情、未登录/登录状态、购物车、个人中心、订单列表、收货地址和结算页；同时核对关键页面数据、控制台、网络请求和截图。测试过程中未创建订单或修改业务数据。

本次报告：

- [小程序运行态报告](results/miniprogram-runtime-2026-10-16/report.md)
- `results/miniprogram-runtime-2026-10-16/01-home.jpg` 至 `10-order-list.jpg` 为公开截图；地址与结算截图因包含测试手机号，仅在本地私人证据目录留存

项目公开配置声明 2.4.0，但本机尝试切换时开发者工具运行时回退至 3.17.4，因此 2.4.0 没有计入通过矩阵。测试后已恢复原本的 3.17.3 私有配置。

### 微信小程序静态兼容性预检

对 41 个页面、4 个 TabBar 入口、108 个 JSON 文件和页面四件套进行 154 项检查，结果为 154 PASS、0 FAIL。

识别到的运行态关注点：

- 项目基础库固定为 2.4.0，需要和当前稳定基础库进行对比回归；
- `127.0.0.1` 仅适用于开发者工具，真机需使用局域网地址或测试环境 HTTPS 域名；
- `wx.getSystemInfo`、`wx.chooseImage` 需要在目标基础库和真机上关注废弃提示与授权差异；
- `debug=true` 适用于测试环境，发布构建前应关闭。

执行脚本：

```powershell
node .\test-compatibility\scripts\run_miniprogram_static_check.js
```

静态预检不能替代开发者工具模拟器和真机运行测试。

## 测试边界

- Chrome 和 Edge 都基于 Chromium，当前结果不能替代 Safari/WebKit 验证；
- 桌面浏览器移动视口用于验证响应式布局，不能完全替代真实手机浏览器；
- 自动巡检侧重渲染、资源、控制台和网络错误，业务数据正确性由功能测试和接口测试补充；
- 真机权限、键盘、相册、网络切换和微信版本差异必须通过真实设备补测。
