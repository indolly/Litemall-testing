# Litemall 兼容性测试完整执行步骤

## 1. 目标与结论边界

兼容性测试的核心不是“打开页面看一眼”，而是让同一组业务场景在不同浏览器、系统、屏幕、微信版本和基础库上重复执行，再比较功能、显示、交互、网络与权限是否一致。

本项目已经形成的真实执行结果：

- H5：Chrome 155、Edge 155；桌面 1440×900、移动视口 390×844；28 项通过。
- 微信小程序：微信开发者工具 iPhone 12/13 Pro 模拟器、微信 8.0.5、基础库 3.17.3；12 项通过。
- 小程序静态预检：154 项通过。静态预检属于兼容性测试前置检查，不能代替真机执行。

Firefox、Safari、Android/iOS 真机只有在实际执行并保存设备信息和证据后，才能写入“已通过”矩阵。

## 2. 环境矩阵设计

按风险优先选择最小有效矩阵：

| 端 | 环境 | 主要价值 | 优先级 |
| --- | --- | --- | --- |
| H5 | Windows + Chrome | 主流 Chromium 基线 | P0 |
| H5 | Windows + Edge | Windows 企业常用浏览器 | P0 |
| H5 | Windows + Firefox | Gecko 引擎差异 | P0 |
| H5 | Android + Chrome | 真机触控、键盘、网络、分辨率 | P0 |
| H5 | Android 微信内置浏览器 | WebView 与微信环境差异 | P0 |
| H5 | iPhone + Safari | WebKit 引擎差异 | P1 |
| H5 | iPhone 微信内置浏览器 | iOS WebView 差异 | P1 |
| 小程序 | 微信开发者工具 iOS 模拟器 | 快速基线回归 | P0 |
| 小程序 | Android 微信真机 | Android 系统与微信版本差异 | P0 |
| 小程序 | iPhone 微信真机 | iOS 权限和系统组件差异 | P1 |
| 小程序 | 最低支持基础库 + 当前稳定基础库 | API 与组件版本兼容 | P1 |

如果设备有限，至少完成 Chrome、Edge、Firefox、Android 真机 Chrome、Android 微信内置浏览器、微信开发者工具和一台微信真机。缺失环境在报告中写“未覆盖”，不能写“通过”。

## 3. 测试前准备

1. 启动 Docker MySQL 和 Litemall 后端，确认 `http://127.0.0.1:8081/wx/home/index` 返回成功。
2. 启动 H5 服务，电脑浏览器访问首页确认可用。
3. 准备专用测试账号、可售商品、库存、收货地址和可清理订单。
4. 记录版本：操作系统、浏览器/微信版本、设备型号、屏幕尺寸、小程序基础库。
5. 真机不能访问电脑的 `127.0.0.1`。手机和电脑连接同一局域网，H5 和 API 改用电脑局域网 IP；如果小程序受合法域名限制，则使用 HTTPS 测试环境域名。
6. 清理上一轮购物车和订单测试数据，确保各环境起点一致。

## 4. 统一核心场景

每个目标环境都执行同一套场景：

| 编号 | 场景 | 关键检查点 |
| --- | --- | --- |
| CT-01 | 首页加载 | Banner、商品图片、文字、TabBar、首屏耗时、无白屏 |
| CT-02 | 分类切换 | 一级/二级分类可点，列表更新，选中状态正确 |
| CT-03 | 搜索商品 | 键盘弹出/收起正常，中文输入正常，结果一致 |
| CT-04 | 商品详情 | 轮播、规格、价格、库存、长图/富文本无错位 |
| CT-05 | 登录 | 输入框、密码、按钮、错误提示、登录态保存正常 |
| CT-06 | 加入购物车 | 规格选择、数量、角标和购物车数据一致 |
| CT-07 | 购物车编辑 | 勾选、改数量、删除、金额联动正常 |
| CT-08 | 地址列表/新增 | 输入法、地区选择、手机号校验、保存和回显正常 |
| CT-09 | 提交订单前确认 | 地址、商品、运费、合计一致；不实际支付 |
| CT-10 | 订单列表/详情 | 状态、金额、图片、返回导航一致 |
| CT-11 | 前后台切换 | 切后台后恢复，页面和登录态不丢失 |
| CT-12 | 弱网/断网恢复 | 有明确提示，恢复网络后可重试，不重复提交 |

## 5. H5 逐环境执行步骤

对 Chrome、Edge、Firefox、Android Chrome、微信内置浏览器、iOS Safari 逐一执行：

1. 清除该浏览器当前站点缓存和登录态。
2. 打开首页，记录首屏是否白屏、布局是否溢出、图片是否破损。
3. 按 CT-01 至 CT-10 完成业务冒烟；每一步比较数据和交互是否与基线一致。
4. 在输入页面检查软键盘是否遮挡输入框和按钮；关闭键盘后页面是否复位。
5. 检查返回键、浏览器返回、刷新、横竖屏切换、缩放后布局。
6. 通过开发者工具或抓包查看是否出现 JavaScript 异常、4xx/5xx、资源加载失败和重复请求。
7. 执行 CT-11、CT-12，重点观察恢复后是否重复加购或重复提交。
8. 每个环境至少保存：首页、商品详情、购物车、地址、订单页截图，以及一张版本信息截图。
9. 发现差异时先在基线环境复测，再换第二设备复测，区分产品缺陷、兼容缺陷和环境问题。

桌面自动巡检可运行：

```powershell
node .\test-compatibility\scripts\run_h5_compatibility.js
```

自动结果只覆盖渲染、资源、控制台和网络基础错误；触控、键盘、权限和真实 WebView 仍需人工真机验证。

## 6. 微信小程序逐环境执行步骤

1. 在微信开发者工具导入 `litemall-wx`，确认编译无产品错误。
2. 记录工具版本、模拟器型号、微信版本和基础库版本。
3. 使用当前稳定基础库执行 CT-01 至 CT-10，保存控制台、网络和关键页面截图。
4. 切换到项目声明的最低支持基础库重新编译，确认基础库确实切换成功后再执行核心冒烟。
5. 使用“预览/真机调试”在 Android 微信运行同一场景；再在 iPhone 微信复测。
6. 真机重点检查授权弹窗、相册/相机、地区选择器、系统键盘、返回手势、前后台切换和网络切换。
7. 比较 Android 与 iOS 的字号、状态栏、安全区、底部按钮、图片裁剪和滚动表现。
8. 在地址和订单截图中对手机号、姓名、详细地址、Token 进行打码；未脱敏原图只保存在本地私人证据目录。
9. 退出测试账号，清理购物车、地址和未支付订单，避免污染下轮结果。

静态预检可运行：

```powershell
node .\test-compatibility\scripts\run_miniprogram_static_check.js
```

## 7. 专项兼容检查

- 显示：横向溢出、文字截断、图片拉伸、刘海/安全区、深色模式。
- 交互：点击热区、连续点击、返回手势、滚动穿透、弹窗层级。
- 输入：中文、英文、数字、粘贴、最大长度、表情、软键盘遮挡。
- 权限：拒绝后再次触发、系统设置修改权限后返回、相册/相机差异。
- 网络：Wi-Fi/移动网络切换、断网、弱网、超时、恢复后的重试和幂等。
- 缓存：首次安装、升级覆盖、清缓存、登录过期、前后台恢复。
- 版本：最低支持版本、当前稳定版本、升级后的数据和登录态兼容。

## 8. 证据与缺陷规范

截图命名：

```text
端-系统-浏览器或微信版本-场景-结果-日期.png
```

示例：

```text
H5-Windows11-Firefox-商品详情-PASS-20261018.png
MiniProgram-Android14-WeChat8.x-地址保存-FAIL-20261018.png
```

每条兼容性缺陷至少记录：环境、前置条件、步骤、实际结果、预期结果、复现率、对比环境、截图/视频、控制台或网络证据。只有某环境失败、基线环境通过，才优先判断为兼容性问题；所有环境都失败时更可能是功能缺陷。

## 9. 报告统计口径

- 计划数：矩阵中的“环境 × 场景”总数。
- 通过数：已实际执行且全部检查点符合预期。
- 失败数：有可复现差异并已登记缺陷。
- 阻塞数：环境、账号、域名或设备问题导致无法执行。
- 未执行数：尚未实际操作，不能计入通过率。
- 通过率：`通过数 / (计划数 - 阻塞数 - 未执行数)`。

报告结论要写清覆盖边界，例如：“Chrome 与 Edge 桌面/移动视口通过；微信开发者工具 iOS 模拟器通过；Firefox、Safari 与 Android/iOS 真机结论以对应执行记录为准。”
